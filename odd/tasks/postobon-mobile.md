## Problem and decisions
The dashboard already has technician permissions and catalogs but no mobile catalog API or native transport. Browser TCP cannot configure Z2. Existing private cloud already reports `playMode`, `deviceClass`, and `heartbeatCount`; use them to verify requested settings. A new `lastSeenIso` alone is insufficient because connect/applyFields also update it. Sync classes A–O map to 0–14; exclude P. Individual mode uses class0; sync mode chooses A–O. Send/read local opcode0x17 before Wi-Fi opcode0x64, and never equate socket write with verified configuration. Administrative groups remain unrelated.

## Acceptance criteria
- Login uses individual, expiring, scoped Sanctum tokens and secure mobile storage. Mobile tokens cannot control devices through legacy API routes, including when issued to superadmin. Role changes are checked on requests.
- Lists combine Z2/WL35, expose safe DTOs only, paginate/filter, and distinguish online/offline/unknown without synchronous full inventory sync per mobile request. No device edit/control UI.
- Establishment and business-type CRUD honors existing rules, blocks deletion of linked records and never reads back Wi-Fi passwords.
- Onboarding is owner-scoped, idempotent and recoverable across AP/Internet transitions. Password stays in memory; no secrets in logs, payload events or task docs. Assignment/name commit only after fresh server evidence for expected identity and requested sync settings; conflicts do not silently reassign.
- Native framing handles UTF-8 byte lengths, fragmented/concatenated frames and timeouts. Identity, name, sync and Wi-Fi commands use documented protocol; uncertain readback stays unverified. Unknown IP/ACK/profile/firmware are explicit, not invented.
- T8 accepted user correction: enable onboarding by default without requiring firmware host/port. Preserve existing network.cfg unless an explicit per-session cloud_domain override is chosen through the app cloud-settings menu. Domain changes use only documented complete bind; require configured public non-privileged enrollment identifier, never infer empty/default credentials. Freeze any chosen target in the session and recovery/idempotence, apply only to future onboarding; no direct existing-device controls.
- Match original logo, Inter and palette in native UI; provide three main tabs and functional auth, catalog and onboarding screens, including sync-class selector.
- App typecheck/tests/export and backend isolated tests/Pint pass where environment permits. Physical Android/iPhone validation and signed distribution remain honestly pending if hardware/signing are unavailable.
